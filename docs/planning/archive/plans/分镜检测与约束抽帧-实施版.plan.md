# 分镜检测与约束抽帧实施版

## 1. 目标

将当前 [`narrate_segment_with_duration`](../../python/narration/src/narration/narrate.py) 中直接调用 [`extract_frames_base64`](../../python/narration/src/narration/frames.py) 的模式，升级为：

1. 对整段视频做一次离线预处理，产出可缓存的 frame pool
2. 旁白生成时优先从 frame pool 中按时间窗取帧
3. 仅当该时间窗在 pool 中零命中时，才局部回退到 `extract_frames_base64`

目标不是一次性做出最复杂的选帧算法，而是先把“单主路径 + 可缓存 + 可验证”的工程骨架搭起来。

## 2. 当前基线

当前代码状态：

- [`subtitle_analysis`](../../python/subtitle_analysis/src/subtitle_analysis/analyze.py) 负责从字幕推导无字幕时间窗
- [`subtitle_analysis/pipeline.py`](../../python/subtitle_analysis/src/subtitle_analysis/pipeline.py) 负责把这些时间窗送到 narration / polish / speech / embed
- [`narration/narrate.py`](../../python/narration/src/narration/narrate.py) 对每个旁白时间窗直接做均匀抽帧
- [`movieteller_config`](../../python/movieteller_config/src/movieteller_config/schema.py) 尚无 frame pool / clip / pyscenedetect / mmr 相关配置

因此这次改造的关键不是改字幕分析，而是增加一个“视频预处理帧池层”，再把 narration 的取帧逻辑切到这条新主路径。

## 3. 设计决策

### 3.1 单主路径

- 不引入 `narration_frame_source=uniform|frame_pool` 这类长期并行模式
- narration 的主路径固定为 `frame_pool`
- 唯一允许保留的均匀抽帧逻辑，是“窗内零命中时”的局部回退

### 3.2 fail fast

- 如果调用 narration 时要求走 frame pool，但 manifest 缺失、schema 不兼容、路径错误，应直接失败
- 不允许在这些错误场景下静默回退到旧的全局均匀抽帧

### 3.3 首版默认策略

- 非台词 shot 采样策略默认 `fixed_max`
- 即未配置 `pool_frames_per_shot_rate` 时，每个非台词 shot 固定采 `pool_frames_per_shot_max` 帧
- 台词镜判定规则首版保持保守：shot 与任一字幕 cue 重叠超过阈值，则整镜跳过
- Query 首版优先做“按时间窗过滤 + 按 shot 分配预算 + shot 内选择”，不追求复杂的全局最优

### 3.4 分阶段实现

不要一口气把 PySceneDetect、CLIP、两轮去重、MMR、CLI、缓存键一次全接完。建议按三阶段推进：

1. `build_pool` 最小闭环
2. CLIP + 两轮去重
3. Query + narration 接入

## 4. 模块边界

建议新增独立包：

- `python/video_frame_pool/`

职责划分如下：

| 模块 | 职责 |
|------|------|
| `video_frame_pool` | 建池、缓存键、manifest/npz 读写、shot 采样、CLIP 去重 |
| `narration/query_frames.py` | Query 阶段的时间过滤、预算拆分、shot 内选帧 |
| `narration/narrate.py` | 调用 frame pool Query；零命中时调用 `extract_frames_base64` |
| `subtitle_analysis` | 继续只负责“哪些时间窗需要旁白” |
| `movieteller_config` | 增加 frame pool / clip / pyscenedetect / mmr 配置 |

不建议把建池逻辑直接塞进 `narration/frames.py`，否则该模块会同时承担“ffmpeg 抽帧工具”和“全片预处理系统”两类职责。

## 5. 数据契约

### 5.1 pool 目录

建议目录结构：

```text
{video_stem}.frame_pool/
  manifest.jsonl
  embeddings.npz
  shots.json
  build_config.json
  images/
    000001.png
    000002.png
```

### 5.2 manifest schema

`manifest.jsonl` 每行一个保留帧：

```json
{
  "schemaVersion": 1,
  "shotId": 12,
  "tSec": 134.280,
  "imageRef": "images/000123.png",
  "embeddingIndex": 122
}
```

约束：

- `schemaVersion` 必填，用于 fail fast
- `shotId` 必须和 `shots.json` 对齐
- `tSec` 必须是视频时间轴坐标
- `embeddingIndex` 指向 `embeddings.npz` 中的同序向量

### 5.3 shots schema

`shots.json` 建议保存全部镜头，而不只是入池镜头：

```json
{
  "schemaVersion": 1,
  "videoPath": "harrypotter.mp4",
  "shots": [
    {
      "shotId": 12,
      "startSec": 133.9,
      "endSec": 136.8,
      "isDialogue": false
    }
  ]
}
```

这样便于调试“为什么这个窗没有入池帧”。

## 6. 配置方案

考虑到当前 [`Settings`](../../python/movieteller_config/src/movieteller_config/schema.py) 仍是平铺结构，首版建议继续使用前缀化平铺字段，避免为了这个功能同时重构整个 config schema。

建议新增：

| 配置项 | 默认值 | 说明 |
|------|------:|------|
| `frame_pool_manifest` | `null` | narration/query 读取的 manifest 路径 |
| `pool_frames_per_shot_min` | `1` | 非台词 shot 最少采样帧数 |
| `pool_frames_per_shot_max` | `3` | 非台词 shot 最多采样帧数 |
| `pool_frames_per_shot_rate` | `null` | 可选时长采样率 |
| `pool_miss_uniform_max_frames` | `24` | 零命中时局部均匀抽帧数 |
| `pool_dedupe_shot_cosine_threshold` | `0.95` | 镜内去重阈值 |
| `pool_dedupe_global_cosine_threshold` | `0.99` | 全局去重阈值 |
| `dialogue_overlap_threshold` | `0.05` | 判定台词镜的重叠阈值 |
| `pyscenedetect_merge_sec` | `0.25` | 极短镜合并阈值 |
| `clip_model_id` | 具体实现选定 | CLIP 模型名 |
| `clip_pretrained` | 具体实现选定 | CLIP 权重名 |
| `mmr_query_lambda` | `0.5` | MMR 权重 |
| `mmr_query_vector` | `shot_centroid` | shot 内 MMR query 定义 |

说明：

- 这批配置应进入 `default.yaml`、`schema.py`、`loader.py`
- `pool_*` 和 `clip_*` 变更要进入建池缓存键
- `mmr_*` 不进入建池缓存键

## 7. CLI 方案

建议新增一个独立 CLI：

```bash
python -m video_frame_pool \
  --video harrypotter.mp4 \
  --srt harrypotter.extracted.srt \
  --output-dir harrypotter.frame_pool
```

CLI 行为：

1. 跑全片分镜
2. 按字幕重叠标记台词镜
3. 对非台词镜均匀采样
4. 导出 PNG
5. 计算 CLIP embedding
6. 两轮去重
7. 写出 manifest / npz / shots / build_config

`subtitle_analysis --narrate` 侧建议新增：

- `--frame-pool-manifest`
- 可选 `--build-pool-first`

首版也可以不做自动建池，只要求显式先跑 `python -m video_frame_pool`。

## 8. Python 接口草案

### 8.1 build pool

```python
def build_frame_pool(
    *,
    video_path: str,
    srt_path: str,
    output_dir: str,
    settings: Settings | None = None,
) -> FramePoolBuildResult:
    ...
```

### 8.2 query frames

```python
def query_frame_pool(
    *,
    manifest_path: str,
    start_sec: float,
    end_sec: float,
    budget: int,
    settings: Settings | None = None,
) -> QueryFramePoolResult:
    ...
```

返回结果建议显式区分来源：

```python
@dataclass(frozen=True)
class QueryFramePoolResult:
    source: str  # "pool" | "uniform_fallback"
    frames_base64_png: tuple[str, ...]
    frame_times_sec: tuple[float, ...]
    shot_ids: tuple[int | None, ...]
```

### 8.3 narration 集成

[`narrate_segment_with_duration`](../../python/narration/src/narration/narrate.py) 改造后伪代码：

```python
duration = segment_duration_sec(...)
try:
    query = query_frame_pool(
        manifest_path=cfg.frame_pool_manifest,
        start_sec=start_sec,
        end_sec=end_sec,
        budget=cfg.max_frames_per_segment,
        settings=cfg,
    )
    frames = list(query.frames_base64_png)
except PoolWindowMiss:
    frames = extract_frames_base64(
        ...,
        max_frames=cfg.pool_miss_uniform_max_frames,
    )
```

注意：

- “没有 manifest” 和 “窗内零命中” 不是一回事
- 前者报错，后者回退

## 9. Query 算法固定版

实现前建议明确固定为以下顺序：

1. 从 manifest 取出 `T0 <= tSec <= T1` 的记录
2. 若结果为空，抛 `PoolWindowMiss`
3. 按 `shotId` 分组
4. 计算各 shot 与 `[T0, T1]` 的相交时长
5. 用 largest remainder 把总预算 `B` 拆成每个 shot 的 `B_s`
6. 在每个 shot 内做选择
7. 合并结果并按 `tSec` 排序

首版建议 shot 内选择先做一个可替换策略：

- 候选数 `<= B_s`：全部保留
- 候选数 `> B_s`：先用“时间均匀覆盖”实现
- MMR 在第二步替换进去

这样先把接口和主路径跑通，再引入语义去冗余。

## 10. 三阶段实施内容

### 阶段一：最小可运行帧池

目标：先建立预处理层，不接 CLIP。

包含：

- `video_frame_pool` 包脚手架
- PySceneDetect 全片分镜
- 台词镜判定
- 非台词镜按 `fixed_max` 采样
- 输出 `images/`、`shots.json`、`manifest.jsonl`
- narration 侧先支持读取 manifest 并按时间过滤取帧
- 零命中时回退 `extract_frames_base64`

不包含：

- CLIP embedding
- 两轮去重
- MMR

验收标准：

- 能对一个视频显式建池
- narration 能消费 pool
- 缺 manifest 报错
- 窗内零命中时按 `pool_miss_uniform_max_frames` 回退

### 阶段二：CLIP 与去重

目标：降低池内重复帧。

包含：

- `embeddings.npz`
- 镜内去重
- 全局去重
- `build_config.json`
- 缓存键
- mock embedding 单测

验收标准：

- 镜内不存在超过 shot 阈值的保留帧对
- 全局不存在超过 global 阈值的保留帧对
- 改 `pool_dedupe_*` 或 `clip_*` 参数会触发重建

### 阶段三：shot 内选择优化

目标：把 Query 由“按时间均匀覆盖”升级为“shot 内选择策略”。

包含：

- `narration/query_frames.py`
- 预算分配
- shot 内 MMR 或等价选择函数
- 单测覆盖预算分配和排序

验收标准：

- 送 LLM 帧数始终 `<= B`
- 不同 shot 都有机会按配额进入结果
- 结果按时间排序稳定

## 11. 测试清单

建议至少覆盖：

- manifest 缺失时报错
- manifest schema version 不匹配时报错
- 窗内零命中时触发 uniform fallback
- fallback 的 `max_frames == pool_miss_uniform_max_frames`
- 台词镜不入池
- 单 shot 候选数小于预算时全保留
- 多 shot 按 largest remainder 拆预算
- 去重时“保留更早 `tSec`”规则稳定

## 12. 风险与后续

当前 plan 最大的真实风险有两个：

1. “台词镜整镜跳过”会丢掉部分本可用于场景理解的画面
2. MMR 在无文本 query 的情况下不一定比“时间覆盖 + 去重”明显更优

因此建议首版先以工程确定性为先：

- 先把预处理层搭好
- 先把 manifest 契约稳定下来
- 先让 narration 从“直接抽帧”迁到“查池取帧”

之后再根据实际视频效果迭代：

- 台词镜按比例裁剪而非整镜跳过
- 跨 shot 二次重排
- 用文本 query 或上一段旁白上下文辅助选帧

## 13. 推荐执行顺序

建议按以下顺序开工：

1. `movieteller_config` 增加 frame pool 配置
2. 新增 `video_frame_pool` 包与 CLI
3. 输出最小版 manifest / shots / images
4. narration 接入 manifest 查询与零命中回退
5. 为 `subtitle_analysis --narrate` 增加 `--frame-pool-manifest`
6. 再做 CLIP、去重和 MMR

这样可以最快拿到一条真实可跑的主链路，而不是先把所有算法细节做满。
